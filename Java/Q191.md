### Java 힙 영역 객체 생명주기 및 GC 루트

#### 1. 핵심 정의

*   **Java 힙 영역**: 모든 객체(인스턴스)와 배열이 생성되는 런타임 데이터 영역입니다. 이 영역은 JVM에 의해 관리되며, 더 이상 참조되지 않는 객체는 가비지 컬렉터(GC)에 의해 메모리에서 해제됩니다.
*   **객체 생명주기**: 객체가 생성되어 힙에 할당되고, 사용되다가 더 이상 참조되지 않아 GC 대상이 되고, 최종적으로 메모리에서 해제되는 일련의 과정입니다.

#### 2. 동작 원리

Java 힙 영역은 일반적으로 Young Generation, Old Generation, (선택적으로) Metaspace 등으로 나뉘며, 객체는 주로 Young Generation에서 생성됩니다.

*   **객체 생성 및 승격**:
    *   새로운 객체는 대부분 Young Generation의 Eden 영역에 할당됩니다.
    *   Eden 영역이 가득 차면 Minor GC가 발생하여 살아있는 객체는 Survivor 0 또는 Survivor 1 영역으로 이동합니다.
    *   이 과정을 여러 번 거치면서 특정 임계값(age) 이상 살아남은 객체는 Old Generation으로 승격(Promotion)됩니다.
    *   Old Generation이 가득 차면 Major GC (또는 Full GC)가 발생하여 Old Generation의 객체를 정리합니다.
*   **가비지 컬렉터의 '살아있는 객체' 판단 (GC 루트)**:
    *   가비지 컬렉터는 **'도달 가능성(Reachability)'**이라는 개념을 사용하여 객체의 생존 여부를 판단합니다. 즉, 어떤 객체가 GC 루트로부터 직간접적으로 참조되고 있다면 '살아있는 객체'로 간주하고 수집 대상에서 제외합니다.
    *   **GC 루트(GC Roots)**는 힙 영역 외부에 존재하며, 항상 참조되고 있다고 가정하는 객체들의 집합입니다. 주요 GC 루트는 다음과 같습니다.
        *   **스택 영역의 로컬 변수**: 현재 실행 중인 메서드의 스택 프레임 내에 있는 지역 변수들이 참조하는 객체.
        *   **메서드 영역의 정적 변수**: 클래스 레벨에 선언된 `static` 필드들이 참조하는 객체.
        *   **네이티브 메서드 스택의 JNI(Java Native Interface) 참조**: JNI를 통해 호출된 네이티브 코드에서 생성된 객체 참조.
        *   **실행 중인 스레드**: 모든 활성 스레드 자체.
        *   **JVM 내부에서 사용하는 특수 참조**: 예를 들어, 시스템 클래스 로더에 의해 로드된 클래스 객체 등.
    *   GC는 이 GC 루트에서부터 객체 그래프를 탐색하여 도달 가능한 모든 객체를 '살아있는 객체'로 표시하고, 도달 불가능한 객체들을 '수집 대상'으로 판단하여 메모리에서 해제합니다.

#### 3. 실무에서 주의할 점

*   **메모리 누수 방지**: 더 이상 사용되지 않는 객체가 GC 루트로부터 계속 참조되어 메모리에서 해제되지 않는 **메모리 누수(Memory Leak)**에 주의해야 합니다. 특히, `static` 컬렉션에 객체를 추가하고 제거하지 않거나, 이벤트 리스너를 등록 후 해제하지 않는 경우 등이 대표적인 원인입니다.
*   **강한 참조(Strong Reference) 관리**: 기본적으로 Java의 모든 참조는 강한 참조입니다. 불필요한 강한 참조를 오래 유지하면 GC가 객체를 수집하지 못하게 되므로, 객체 사용이 끝났다면 참조를 `null`로 명시적으로 해제하는 습관을 들이는 것이 좋습니다.
*   **GC 튜닝**: 애플리케이션의 특성(객체 생성 빈도, 객체 수명 등)에 따라 적절한 GC 알고리즘(Parallel, CMS, G1, ZGC 등)을 선택하고 힙 사이즈를 튜닝하여 GC 오버헤드를 최소화하고 성능을 최적화해야 합니다.
*   **Weak/Soft/Phantom Reference 활용**: 캐시 구현 등 특정 상황에서는 `WeakReference`나 `SoftReference`와 같은 약한 참조를 사용하여 GC가 더 유연하게 객체를 수집하도록 유도할 수 있습니다.
