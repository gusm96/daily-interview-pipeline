## Java String 객체의 불변성

### 1. 핵심 정의
Java의 `String` 객체는 한 번 생성되면 그 내부의 문자열 값을 변경할 수 없는 불변(immutable) 객체입니다. 즉, `String` 변수에 새로운 값을 할당하는 것처럼 보여도 실제로는 기존 객체가 변경되는 것이 아니라 새로운 `String` 객체가 생성되어 할당되는 방식입니다.

### 2. 동작 원리
*   **힙(Heap) 메모리:** `String` 객체는 힙 메모리에 저장됩니다.
*   **String Pool:** 동일한 문자열 리터럴을 사용하는 경우, JVM은 `String Pool`이라는 특별한 메모리 영역에서 기존 객체를 재사용하여 메모리 사용을 최적화합니다.
*   **새로운 객체 생성:** `String` 객체의 내용을 변경하는 연산(예: `concat()`, `substring()`, `+` 연산자)은 기존 객체를 수정하는 것이 아니라 항상 새로운 `String` 객체를 생성하여 반환합니다.

### 3. 불변성으로 얻을 수 있는 장점
*   **보안:** 문자열은 파일 경로, 네트워크 연결 정보, 사용자 비밀번호 등 민감한 정보를 다루는 경우가 많습니다. 불변성은 이러한 문자열이 예기치 않게 변경되는 것을 방지하여 보안을 강화합니다.
*   **스레드 안전성 (Thread-Safety):** 여러 스레드가 동시에 `String` 객체에 접근하더라도 객체의 상태가 변경될 염려가 없으므로 별도의 동기화 메커니즘 없이 안전하게 공유할 수 있습니다.
*   **캐싱 및 성능 최적화:** `String Pool`을 통해 동일한 문자열 리터럴에 대해 하나의 객체만 생성하고 재사용함으로써 메모리 사용량을 줄이고 객체 생성 비용을 절감할 수 있습니다. 또한, 해시 코드(hash code)를 한 번 계산하면 변경되지 않으므로 `HashMap`이나 `HashSet`과 같은 컬렉션에서 키로 사용될 때 성능 이점을 얻을 수 있습니다.
*   **보안 해시 코드:** `String` 객체의 해시 코드는 불변성을 기반으로 한 번 계산되면 캐시되어 재사용됩니다. 이는 `HashMap`과 같은 해시 기반 컬렉션에서 키로 사용될 때 성능을 향상시킵니다.

### 4. String 연산 시 발생할 수 있는 잠재적인 성능 문제
`String` 객체의 불변성으로 인해 문자열을 반복적으로 연결하거나 수정하는 연산은 성능 저하를 유발할 수 있습니다. 예를 들어, `String str = ""; for (int i = 0; i < 1000; i++) { str += "a"; }`와 같은 코드는 루프가 돌 때마다 새로운 `String` 객체가 생성되고 이전 객체는 가비지 컬렉션 대상이 되어 많은 메모리 할당 및 해제 오버헤드를 발생시킵니다.

### 5. 해결을 위한 효과적인 방법
*   **`StringBuilder` 또는 `StringBuffer` 사용:**
    *   **`StringBuilder`:** 단일 스레드 환경에서 문자열을 효율적으로 조작해야 할 때 사용합니다. 동기화 오버헤드가 없어 `StringBuffer`보다 빠릅니다.
    *   **`StringBuffer`:** 멀티 스레드 환경에서 스레드 안전하게 문자열을 조작해야 할 때 사용합니다. 내부적으로 동기화(synchronized)되어 있어 `StringBuilder`보다 성능은 떨어지지만 안전합니다.
*   **적절한 초기 용량 설정:** `StringBuilder`나 `StringBuffer`를 사용할 때, 최종 문자열의 예상 길이를 미리 알고 있다면 생성자에 초기 용량을 지정하여 불필요한 배열 재할당을 줄일 수 있습니다.
*   **`String.join()` 사용:** 여러 문자열을 구분자와 함께 연결할 때는 `String.join()` 메서드를 사용하는 것이 가독성과 성능 면에서 유리합니다.
