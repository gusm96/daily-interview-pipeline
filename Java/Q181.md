## Java 애플리케이션 힙(Heap) 영역 외 메모리 사용량 증가 진단 및 해결

면접관님, 이 질문은 JVM 내부 동작과 OS 레벨의 메모리 관리에 대한 이해를 묻는 좋은 질문입니다. Java 애플리케이션에서 힙 영역 외 메모리 사용량이 비정상적으로 증가하는 경우, 일반적으로 다음과 같은 원인들을 의심해볼 수 있으며, 이를 진단하고 해결하기 위한 방법들을 설명드리겠습니다.

---

### 1. 핵심 정의

Java 애플리케이션의 메모리 사용량은 크게 JVM 힙(Heap) 영역과 힙 외(Off-Heap) 영역으로 나눌 수 있습니다. 힙 영역은 GC(Garbage Collection)의 관리 대상이며 객체 인스턴스들이 저장되는 공간인 반면, 힙 외 영역은 JVM 자체 코드, JNI(Java Native Interface)를 통해 할당된 메모리, 직접 바이트 버퍼(Direct Byte Buffer), 스레드 스택, 메타스페이스(Metaspace) 등 GC의 직접적인 관리 대상이 아닌 메모리 공간을 의미합니다. 힙 외 메모리 사용량 증가는 GC로는 해결할 수 없는 문제이므로 진단이 더 까다로울 수 있습니다.

### 2. 동작 원리 및 의심 원인

힙 외 메모리 사용량 증가는 주로 다음과 같은 원인들로 인해 발생합니다.

*   **JNI(Java Native Interface)를 통한 네이티브 메모리 누수:**
    *   **원리:** Java 코드가 C/C++과 같은 네이티브 코드를 호출할 때 JNI를 사용합니다. 네이티브 코드에서 `malloc` 등으로 할당한 메모리를 `free`하지 않거나, 자원 해제 로직에 문제가 있을 경우 OS 레벨에서 메모리 누수가 발생합니다.
    *   **의심 상황:** 특정 JNI 라이브러리를 사용하거나, 외부 시스템과 연동하는 부분에서 메모리 사용량이 지속적으로 증가할 때.

*   **Direct Byte Buffer 누수:**
    *   **원리:** `java.nio.ByteBuffer.allocateDirect()`를 통해 할당되는 메모리로, OS의 네이티브 메모리를 직접 사용합니다. 이 버퍼는 GC 대상이 아니며, `Cleaner` 메커니즘을 통해 GC가 발생할 때 네이티브 메모리가 해제되도록 예약됩니다. 하지만 버퍼 참조가 너무 오래 유지되거나, GC가 충분히 자주 발생하지 않아 `Cleaner`가 동작하지 못하면 네이티브 메모리가 해제되지 않을 수 있습니다.
    *   **의심 상황:** 대용량 파일 I/O, 네트워크 통신 등 `java.nio` 패키지를 적극적으로 사용하는 애플리케이션에서 메모리 사용량이 증가할 때.

*   **스레드 스택 메모리 과다 사용:**
    *   **원리:** 각 Java 스레드는 고유한 스택 메모리(JVM 스택)를 가집니다. 스레드 수가 너무 많거나, 각 스레드의 스택 크기(`-Xss` 옵션)가 너무 크게 설정되어 있으면 전체 스택 메모리 사용량이 증가합니다.
    *   **의심 상황:** 스레드 풀 설정이 잘못되었거나, 스레드가 제대로 종료되지 않아 스레드 수가 지속적으로 증가할 때.

*   **메타스페이스(Metaspace) 누수:**
    *   **원리:** Java 8부터 PermGen을 대체한 메타스페이스는 클래스 메타데이터를 저장하는 영역입니다. 클래스 로더가 동적으로 생성되고 해제되지 않거나, 클래스 로더 누수가 발생하면 메타스페이스 메모리가 계속 증가할 수 있습니다.
    *   **의심 상황:** 동적으로 클래스를 로드하거나 언로드하는 애플리케이션(예: 플러그인 아키텍처, 웹 서버의 핫 디플로이)에서 메모리 사용량이 증가할 때.

*   **JVM 자체 오버헤드:**
    *   **원리:** JVM 자체도 실행을 위해 일정량의 네이티브 메모리를 사용합니다. JIT 컴파일러 캐시, GC 데이터 구조 등 다양한 내부 구성 요소들이 힙 외 메모리를 사용합니다.
    *   **의심 상황:** JVM 옵션(`-XX:MaxDirectMemorySize`, `-XX:CompressedClassSpaceSize` 등) 설정이 너무 크거나, JVM 버전의 알려진 버그가 있을 때.

### 3. 실무에서 주의할 점 및 진단/해결 방법

힙 외 메모리 문제를 진단하고 해결하기 위해서는 OS 레벨과 JVM 레벨의 다양한 도구를 활용해야 합니다.

*   **OS 레벨 모니터링:**
    *   `top`, `htop`, `free`, `pmap` (Linux), `Activity Monitor` (macOS), `Task Manager` (Windows) 등을 사용하여 프로세스의 전체 메모리 사용량(RSS, VSZ)을 확인하고, 특정 시점에 급증하는지 추이를 관찰합니다.
    *   `pmap -x <pid>` 명령어를 통해 프로세스가 사용하는 메모리 영역별 상세 정보를 확인하여 어떤 종류의 메모리가 증가하는지 힌트를 얻을 수 있습니다.

*   **JVM 레벨 진단 도구:**
    *   **`jcmd <pid> VM.native_memory summary`:** JVM이 할당한 네이티브 메모리 사용량을 카테고리별로 상세하게 보여줍니다. JNI, Direct Buffer, Metaspace, Thread Stack 등 각 영역의 사용량을 파악하는 데 매우 유용합니다.
    *   **`jmap -heap <pid>`:** 힙 영역의 정보를 보여주지만, 힙 외 메모리 문제 진단 시에는 `jcmd`가 더 효과적입니다.
    *   **`jstack <pid>`:** 스레드 덤프를 통해 현재 실행 중인 스레드 수와 각 스레드의 상태를 확인하여 스레드 누수 여부를 판단할 수 있습니다.
    *   **`jstat -gcutil <pid>`:** GC 활동을 모니터링하여 GC가 정상적으로 동작하는지, 힙 영역은 잘 관리되고 있는지 확인합니다. 힙 영역은 정상인데 전체 메모리가 증가한다면 힙 외 메모리 문제일 가능성이 높습니다.

*   **Direct Byte Buffer 누수 진단 및 해결:**
    *   `jcmd <pid> VM.native_memory summary`에서 "Direct" 카테고리 사용량을 확인합니다.
    *   `-XX:MaxDirectMemorySize` 옵션을 적절히 설정하여 최대 사용량을 제한합니다.
    *   `ByteBuffer.allocateDirect()`를 사용하는 코드에서 `buffer.clear()`나 `buffer.compact()`를 호출하여 재사용하거나, `Cleaner`가 동작하도록 참조를 명확히 해제하는지 확인합니다.
    *   `-XX:+PrintGCDetails`와 같은 GC 로그를 통해 GC가 충분히 자주 발생하는지 확인하고, 필요하다면 GC 튜닝을 고려합니다.

*   **JNI 메모리 누수 진단 및 해결:**
    *   `jcmd <pid> VM.native_memory summary`에서 "JNI" 또는 "Other" 카테고리 사용량을 확인합니다.
    *   네이티브 코드에 메모리 할당/해제 로직을 면밀히 검토하고, `valgrind`와 같은 네이티브 메모리 디버깅 도구를 사용하여 누수를 찾아냅니다.
    *   가능하다면 JNI 사용을 최소화하거나, 검증된 라이브러리를 사용합니다.

*   **스레드 스택 메모리 과다 사용 진단 및 해결:**
    *   `jstack`으로 스레드 수를 확인하고, 스레드 풀 설정(최대 스레드 수)을 검토합니다.
    *   `jcmd <pid> VM.native_memory summary`에서 "Thread" 카테고리 사용량을 확인합니다.
    *   `-Xss` 옵션을 너무 크게 설정하지 않았는지 확인하고, 필요한 최소값으로 조정합니다.

*   **메타스페이스 누수 진단 및 해결:**
    *   `jcmd <pid> VM.native_memory summary`에서 "Metaspace" 카테고리 사용량을 확인합니다.
    *   `jmap -histo:live <pid>`를 통해 클래스 로더별 클래스 수를 확인하여 특정 클래스 로더가 해제되지 않고 있는지 파악합니다.
    *   `-XX:MaxMetaspaceSize` 옵션을 설정하여 메타스페이스의 최대 크기를 제한할 수 있습니다.
    *   동적으로 클래스를 로드하는 경우, 클래스 로더가 올바르게 언로드되는지 확인합니다.

이러한 진단 도구와 방법을 통해 힙 외 메모리 사용량 증가의 원인을 체계적으로 파악하고 해결할 수 있습니다.
