## Java 내부 클래스 종류 및 활용

면접관님, Java의 내부 클래스는 클래스 내부에 선언된 클래스로, 외부 클래스의 멤버에 접근할 수 있다는 특징을 가집니다. 이러한 내부 클래스는 크게 네 가지 종류로 나눌 수 있으며, 각각의 특성과 활용 시점이 다릅니다.

---

### 1. 정적 중첩 클래스 (Static Nested Class)

*   **핵심 정의**: `static` 키워드로 선언된 내부 클래스입니다. 외부 클래스의 인스턴스 없이도 생성될 수 있으며, 외부 클래스의 정적 멤버에만 직접 접근할 수 있습니다.
*   **동작 원리**: 외부 클래스의 인스턴스와 독립적으로 존재하며, 마치 일반적인 최상위 클래스처럼 동작합니다. 다만, 외부 클래스의 private 정적 멤버에도 접근할 수 있다는 점에서 일반 클래스와 차이가 있습니다.
*   **유용성 및 선택 이유**:
    *   **논리적 그룹화**: 외부 클래스와 강하게 연관되어 있지만, 외부 클래스의 인스턴스 데이터에 접근할 필요가 없는 헬퍼 클래스나 유틸리티 클래스를 묶을 때 유용합니다. (예: `OuterClass.Builder` 패턴)
    *   **캡슐화**: 관련 클래스를 한 파일 안에 묶어 코드 가독성과 유지보수성을 높일 수 있습니다.

---

### 2. 멤버 내부 클래스 (Member Inner Class)

*   **핵심 정의**: `static` 키워드 없이 선언된 내부 클래스입니다. 외부 클래스의 인스턴스에 종속적이며, 외부 클래스의 모든 멤버(정적 및 인스턴스)에 직접 접근할 수 있습니다.
*   **동작 원리**: 외부 클래스의 인스턴스가 생성되어야만 멤버 내부 클래스의 인스턴스를 생성할 수 있습니다. 내부적으로 외부 클래스 인스턴스에 대한 숨겨진 참조를 가집니다.
*   **유용성 및 선택 이유**:
    *   **외부 클래스 인스턴스 데이터 접근**: 내부 클래스가 외부 클래스의 인스턴스 변수나 메서드에 빈번하게 접근해야 할 때 유용합니다. (예: 특정 컬렉션의 `Iterator` 구현)
    *   **강한 연관성**: 내부 클래스의 존재 자체가 외부 클래스의 특정 인스턴스와 밀접하게 연결되어 있을 때 사용합니다.

---

### 3. 지역 내부 클래스 (Local Inner Class)

*   **핵심 정의**: 메서드 내부나 스코프 블록 내부에 선언된 클래스입니다. 해당 블록 내에서만 유효하며, 블록 내의 final 또는 effectively final 지역 변수에 접근할 수 있습니다.
*   **동작 원리**: 선언된 블록이 실행될 때만 존재하며, 해당 블록을 벗어나면 접근할 수 없습니다. 컴파일러가 자동으로 외부 스코프의 변수를 캡처하여 내부 클래스에서 사용할 수 있도록 합니다.
*   **유용성 및 선택 이유**:
    *   **일회성 사용**: 특정 메서드 내에서만 필요한 복잡한 로직을 캡슐화하거나, 특정 인터페이스를 구현하는 클래스가 해당 메서드 내에서만 사용될 때 유용합니다.
    *   **코드 응집도**: 관련 로직을 한 곳에 모아 코드의 가독성을 높일 수 있습니다.

---

### 4. 익명 내부 클래스 (Anonymous Inner Class)

*   **핵심 정의**: 이름이 없는 클래스로, 클래스 선언과 동시에 객체를 생성합니다. 주로 인터페이스를 구현하거나 기존 클래스를 상속받아 메서드를 오버라이드할 때 사용됩니다.
*   **동작 원리**: 컴파일 시점에 내부적으로 이름이 부여된 클래스로 변환됩니다. 지역 내부 클래스와 유사하게 선언된 스코프의 final 또는 effectively final 변수에 접근할 수 있습니다.
*   **유용성 및 선택 이유**:
    *   **간단한 일회성 구현**: 단일 메서드만 구현하거나 오버라이드하는 인터페이스나 추상 클래스를 즉석에서 구현할 때 매우 유용합니다. (예: 이벤트 리스너, `Runnable` 구현)
    *   **코드 간결성**: 별도의 클래스 파일을 만들 필요 없이 필요한 위치에서 바로 구현할 수 있어 코드를 간결하게 유지할 수 있습니다.

---

### 실무에서 주의할 점

*   **메모리 누수**: 멤버 내부 클래스는 외부 클래스 인스턴스에 대한 참조를 암묵적으로 가지므로, 내부 클래스 인스턴스가 외부 클래스 인스턴스보다 오래 살아남을 경우 메모리 누수가 발생할 수 있습니다.
*   **직렬화 문제**: 내부 클래스를 직렬화할 때는 외부 클래스도 함께 직렬화될 수 있으므로 주의해야 합니다. 특히 멤버 내부 클래스는 외부 클래스 인스턴스에 대한 참조 때문에 직렬화가 복잡해질 수 있습니다.
*   **가독성**: 너무 깊게 중첩된 내부 클래스는 코드 가독성을 해칠 수 있으므로, 적절한 수준에서 사용하고 필요한 경우 별도의 최상위 클래스로 분리하는 것을 고려해야 합니다.
*   **람다 표현식과의 비교**: Java 8부터 도입된 람다 표현식은 익명 내부 클래스의 많은 부분을 대체할 수 있으며, 특히 함수형 인터페이스를 구현할 때 더욱 간결하고 효율적인 코드를 작성할 수 있게 합니다. 단, 람다는 단일 추상 메서드만 가진 인터페이스에만 적용 가능합니다.

각 내부 클래스의 특성을 이해하고 상황에 맞게 적절히 활용하는 것이 중요합니다.
