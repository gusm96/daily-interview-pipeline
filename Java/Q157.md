## Java에서 스레드 풀을 직접 구현하는 대신 ExecutorService를 사용하는 주된 이유와 ExecutorService의 다양한 구현체들이 각각 어떤 상황에 적합한지 설명해주세요.

### 1. ExecutorService 사용의 주된 이유

ExecutorService를 사용하는 주된 이유는 스레드 관리의 복잡성을 추상화하고, 효율적이며 안정적인 동시성 프로그래밍을 가능하게 하기 위함입니다.

*   **스레드 라이프사이클 관리 자동화:** 스레드 생성, 시작, 종료, 재사용 등 복잡한 스레드 라이프사이클 관리를 ExecutorService가 대신 처리하여 개발자는 비즈니스 로직에 집중할 수 있습니다. 직접 구현 시 발생할 수 있는 스레드 누수, 과도한 스레드 생성 등의 문제를 방지합니다.
*   **자원 효율성 및 성능 최적화:** 스레드 풀을 통해 스레드를 재사용함으로써 스레드 생성 및 소멸에 드는 오버헤드를 줄여 시스템 자원을 효율적으로 사용하고 성능을 향상시킵니다.
*   **안정성 및 견고성:** 스레드 풀의 크기 제한, 작업 큐 관리, 예외 처리 메커니즘 등을 통해 시스템의 안정성을 높이고, 과부하 상황에서도 서비스가 다운되지 않도록 보호합니다.
*   **유연한 확장성:** 다양한 ExecutorService 구현체를 통해 애플리케이션의 요구사항에 맞춰 스레드 풀의 동작 방식을 유연하게 선택하고 확장할 수 있습니다.

### 2. ExecutorService의 다양한 구현체와 적합한 상황

`Executors` 팩토리 클래스를 통해 생성할 수 있는 주요 ExecutorService 구현체들은 다음과 같습니다.

*   **`newFixedThreadPool(int nThreads)`**
    *   **핵심 정의:** 고정된 개수의 스레드를 가진 스레드 풀을 생성합니다. 모든 스레드가 바쁘면, 새로운 작업은 큐에 대기합니다.
    *   **동작 원리:** 지정된 개수만큼의 스레드를 미리 생성하고, 작업이 들어오면 사용 가능한 스레드가 작업을 처리합니다. 스레드가 모두 사용 중이면 작업은 무한 대기 큐(LinkedBlockingQueue)에 저장됩니다.
    *   **적합한 상황:**
        *   CPU 사용량이 많은 작업(CPU-bound task)에 적합합니다.
        *   동시에 처리할 수 있는 작업의 수가 제한적일 때, 시스템 자원(CPU 코어 수)에 맞춰 스레드 수를 고정하여 오버헤드를 줄이고 안정적인 성능을 유지해야 할 때 유용합니다.
        *   예: 이미지 처리, 복잡한 계산, 대규모 데이터 분석 등.

*   **`newCachedThreadPool()`**
    *   **핵심 정의:** 필요에 따라 새로운 스레드를 생성하고, 유휴 스레드는 재사용하는 스레드 풀입니다. 스레드가 60초 동안 유휴 상태이면 종료됩니다.
    *   **동작 원리:** 작업이 제출되면, 사용 가능한 스레드가 있으면 재사용하고, 없으면 새로운 스레드를 생성합니다. 스레드 수는 제한이 없으며, 작업이 없으면 스레드는 60초 후 종료됩니다.
    *   **적합한 상황:**
        *   짧고 비동기적인 작업(I/O-bound task)이 많고, 작업 제출 빈도가 불규칙할 때 적합합니다.
        *   스레드 수가 급격히 변동할 수 있지만, 유휴 스레드를 빠르게 회수하여 자원 낭비를 줄여야 할 때 유용합니다.
        *   예: 네트워크 요청 처리, 파일 I/O, 짧은 웹 서비스 요청 등.

*   **`newSingleThreadExecutor()`**
    *   **핵심 정의:** 단일 스레드를 사용하여 모든 작업을 순차적으로 실행하는 ExecutorService입니다.
    *   **동작 원리:** 하나의 스레드만 존재하며, 모든 작업은 이 스레드에 의해 제출된 순서대로 처리됩니다. 스레드 장애 시 새로운 스레드로 교체됩니다.
    *   **적합한 상황:**
        *   모든 작업이 특정 순서로 실행되어야 하거나, 동시성 문제를 피하고 싶을 때 적합합니다.
        *   단일 스레드에서만 접근해야 하는 공유 자원이 있을 때 유용합니다.
        *   예: 로그 기록, 이벤트 순차 처리, 특정 자원에 대한 단일 접근 보장.

*   **`newScheduledThreadPool(int corePoolSize)`**
    *   **핵심 정의:** 지정된 지연 시간 후 또는 주기적으로 작업을 실행할 수 있는 스레드 풀입니다.
    *   **동작 원리:** `ScheduledExecutorService` 인터페이스를 구현하며, `schedule()`, `scheduleAtFixedRate()`, `scheduleWithFixedDelay()` 메서드를 통해 작업을 예약 실행할 수 있습니다.
    *   **적합한 상황:**
        *   특정 시간 간격으로 반복 실행되어야 하는 작업(예: 배치 작업, 주기적인 데이터 동기화)이나, 특정 지연 시간 후에 실행되어야 하는 작업에 적합합니다.
        *   예: 주기적인 캐시 갱신, 알림 발송, 백업 작업.

### 3. 실무에서 주의할 점

*   **스레드 풀 크기 결정:** `newFixedThreadPool` 사용 시, 스레드 풀의 크기는 애플리케이션의 특성(CPU-bound vs I/O-bound)과 시스템 자원(CPU 코어 수)을 고려하여 신중하게 결정해야 합니다. 너무 작으면 성능 저하, 너무 크면 자원 고갈을 초래할 수 있습니다.
*   **작업 큐 관리:** `newFixedThreadPool`의 무한 대기 큐(LinkedBlockingQueue)는 과도한 작업 제출 시 OOM(Out Of Memory)을 유발할 수 있습니다. 필요에 따라 유한한 크기의 큐(예: `ArrayBlockingQueue`)를 사용하거나, `ThreadPoolExecutor`를 직접 구성하여 `RejectedExecutionHandler`를 통해 작업 거부 정책을 명시적으로 처리하는 것이 좋습니다.
*   **스레드 풀 종료:** 애플리케이션 종료 시 `ExecutorService`의 `shutdown()` 또는 `shutdownNow()` 메서드를 호출하여 스레드 풀을 안전하게 종료해야 합니다. 그렇지 않으면 애플리케이션이 종료되지 않거나 스레드 누수가 발생할 수 있습니다.
*   **예외 처리:** 스레드에서 발생하는 예외는 기본적으로 호출 스레드로 전파되지 않습니다. `Future.get()`을 사용하거나, `UncaughtExceptionHandler`를 설정하여 스레드 내에서 발생하는 예외를 적절히 처리해야 합니다.
*   **`ThreadPoolExecutor` 직접 구성:** `Executors` 팩토리 메서드는 편리하지만, 세부적인 제어가 필요할 때는 `ThreadPoolExecutor` 클래스를 직접 인스턴스화하여 코어 스레드 수, 최대 스레드 수, 유휴 시간, 작업 큐, 스레드 팩토리, 거부 핸들러 등을 명시적으로 설정하는 것이 가장 유연하고 강력한 방법입니다.
