## 데이터베이스 정규화 및 비정규화

### 1. 데이터베이스 정규화의 각 단계와 목적

데이터베이스 정규화는 데이터 중복을 최소화하고, 데이터 무결성을 유지하며, 이상 현상(삽입, 갱신, 삭제 이상)을 방지하기 위해 릴레이션을 분해하는 과정입니다. 각 정규화 단계는 이전 단계의 조건을 만족하면서 추가적인 제약 조건을 적용합니다.

*   **1차 정규형 (1NF)**
    *   **핵심 정의:** 릴레이션의 모든 속성 값이 원자 값(atomic value)을 가져야 합니다. 즉, 하나의 셀에 여러 값이 있거나, 반복되는 그룹이 없어야 합니다.
    *   **동작 원리:** 복합 속성이나 다중 값 속성을 분리하여 각 속성이 단일 값을 갖도록 합니다.
    *   **목적:** 데이터의 구조적 일관성을 확보하고, 관계형 데이터베이스의 기본 형태를 만듭니다.

*   **2차 정규형 (2NF)**
    *   **핵심 정의:** 1NF를 만족하고, 모든 비기본키 속성이 기본키에 대해 완전 함수 종속이어야 합니다. 즉, 부분 함수 종속이 없어야 합니다.
    *   **동작 원리:** 복합 기본키의 일부에만 종속되는 비기본키 속성을 별도의 테이블로 분리합니다.
    *   **목적:** 부분 함수 종속으로 인한 삽입, 갱신, 삭제 이상을 제거합니다.

*   **3차 정규형 (3NF)**
    *   **핵심 정의:** 2NF를 만족하고, 기본키가 아닌 모든 속성이 기본키에 대해 이행적 함수 종속이 없어야 합니다. 즉, 비기본키 속성 간의 종속성이 없어야 합니다.
    *   **동작 원리:** 비기본키 속성이 다른 비기본키 속성에 종속되는 경우, 해당 종속성을 별도의 테이블로 분리합니다.
    *   **목적:** 이행적 함수 종속으로 인한 삽입, 갱신, 삭제 이상을 제거합니다.

*   **보이스-코드 정규형 (BCNF)**
    *   **핵심 정의:** 3NF를 만족하고, 모든 결정자가 후보키여야 합니다. 즉, 모든 함수 종속성 X → Y에서 X가 후보키여야 합니다.
    *   **동작 원리:** 3NF에서 해결하지 못하는, 여러 후보키가 존재하고 그 후보키들이 서로 겹치는 경우 발생하는 이상 현상을 제거합니다.
    *   **목적:** 3NF보다 더 엄격한 조건으로 데이터 중복을 제거하고 이상 현상을 방지하여 데이터 무결성을 극대화합니다. 일반적으로 BCNF는 3NF보다 더 높은 수준의 정규화로 간주됩니다.

### 2. 실무에서 비정규화를 고려할 때의 트레이드오프

비정규화는 정규화된 테이블을 의도적으로 다시 결합하거나 중복 데이터를 추가하여, 특정 쿼리의 성능을 향상시키기 위한 과정입니다. 이는 데이터 중복 증가와 데이터 무결성 관리의 복잡성 증가라는 트레이드오프를 감수해야 합니다.

**구체적인 상황 가정:**
전자상거래 시스템에서 `주문` 테이블과 `상품` 테이블이 정규화되어 있다고 가정해봅시다.
*   `주문` 테이블: `주문ID`, `회원ID`, `상품ID`, `수량`, `주문일시`
*   `상품` 테이블: `상품ID`, `상품명`, `가격`, `재고수량`

**문제 상황:**
관리자 페이지에서 특정 기간 동안의 모든 주문 내역을 조회할 때, 각 주문에 포함된 상품의 `상품명`과 `가격`을 함께 보여줘야 합니다. 이 경우, `주문` 테이블과 `상품` 테이블을 `상품ID`로 조인해야 합니다. 주문 내역이 매우 많아지면, 빈번한 조인 연산으로 인해 쿼리 성능이 저하될 수 있습니다.

**비정규화 고려 및 트레이드오프:**

1.  **비정규화 방법:** `주문` 테이블에 `상품명`과 `가격` 속성을 추가하여 `주문_비정규화` 테이블을 만듭니다.
    *   `주문_비정규화` 테이블: `주문ID`, `회원ID`, `상품ID`, `상품명`, `가격`, `수량`, `주문일시`

2.  **성능 최적화:**
    *   **장점:** 관리자 페이지에서 주문 내역을 조회할 때 `주문_비정규화` 테이블만 조회하면 되므로, 조인 연산이 사라져 쿼리 속도가 크게 향상됩니다. 특히 읽기(Read) 작업이 압도적으로 많은 시스템에서 유리합니다.

3.  **감수해야 할 트레이드오프:**
    *   **데이터 중복:** `상품명`과 `가격` 정보가 `상품` 테이블과 `주문_비정규화` 테이블에 중복 저장됩니다. 이는 저장 공간을 더 많이 사용하게 됩니다.
    *   **데이터 일관성 문제:** `상품` 테이블에서 `상품명`이나 `가격`이 변경될 경우, `주문_비정규화` 테이블의 해당 정보도 함께 갱신해주어야 합니다. 만약 갱신을 누락하면 데이터 불일치(Inconsistency)가 발생하여 잘못된 정보를 제공할 수 있습니다. 이를 해결하기 위해 트리거, 배치 작업, 또는 애플리케이션 로직을 통해 일관성을 유지하는 추가적인 노력이 필요합니다.
    *   **갱신 이상 발생 가능성:** `상품` 정보 변경 시 여러 `주문` 레코드에 걸쳐 있는 중복된 `상품명`, `가격`을 모두 갱신해야 하므로 갱신 작업이 복잡해지고 오류 발생 가능성이 높아집니다.

**결론:**
비정규화는 읽기 성능을 극대화해야 하는 특정 쿼리에 대해 효과적인 전략이 될 수 있지만, 데이터 중복과 일관성 관리의 복잡성 증가라는 명확한 단점을 가집니다. 따라서 비정규화를 결정할 때는 해당 쿼리의 중요도, 읽기/쓰기 작업의 비율, 데이터 일관성 유지 비용 등을 종합적으로 고려하여 신중하게 접근해야 합니다. 일반적으로는 정규화를 우선적으로 고려하고, 성능 병목이 명확하게 식별될 때 제한적으로 비정규화를 적용하는 것이 바람직합니다.
