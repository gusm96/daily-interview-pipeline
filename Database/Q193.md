## 데이터베이스 트랜잭션 롤백(Rollback) 동작 및 내부 메커니즘

### 1. 핵심 정의

롤백은 데이터베이스 트랜잭션의 네 가지 주요 특성 중 하나인 원자성(Atomicity)을 보장하는 핵심 메커니즘입니다. 트랜잭션 도중 오류가 발생하거나 사용자가 명시적으로 취소를 요청할 경우, 해당 트랜잭션 내에서 수행된 모든 변경사항을 트랜잭션 시작 전의 상태로 되돌려 데이터의 일관성을 유지합니다.

### 2. 동작 원리

*   **변경사항 기록:** 트랜잭션이 시작되면, 데이터베이스는 해당 트랜잭션이 데이터를 변경하기 전에 원래 데이터를 별도의 공간에 기록합니다. 이를 일반적으로 **언두(Undo) 정보** 또는 **롤백 세그먼트(Rollback Segment)**라고 부릅니다.
*   **데이터 변경:** 트랜잭션은 실제 데이터 블록을 변경합니다. 이 변경사항은 아직 영구적으로 저장된 것이 아니며, 다른 트랜잭션에게는 아직 커밋되지 않은 상태로 보일 수 있습니다.
*   **롤백 요청/발생:** 트랜잭션 도중 `ROLLBACK` 명령이 실행되거나, 시스템 오류, 제약 조건 위반 등으로 인해 트랜잭션이 더 이상 진행될 수 없게 되면 롤백이 트리거됩니다.
*   **원상 복구:** 데이터베이스는 이전에 기록해 두었던 언두 정보를 사용하여 변경되었던 데이터 블록들을 트랜잭션 시작 전의 원래 상태로 되돌립니다. 이 과정이 완료되면 해당 트랜잭션은 마치 아무런 작업도 수행하지 않은 것처럼 됩니다.

### 3. 내부 메커니즘

데이터베이스는 롤백을 위해 주로 **언두 로그(Undo Log)** 또는 **롤백 세그먼트(Rollback Segment)**를 활용합니다.

*   **언두 로그 (Undo Log):**
    *   트랜잭션이 데이터를 변경하기 전의 원본 데이터를 기록하는 특별한 로그 파일 또는 영역입니다.
    *   각 변경 작업마다 해당 변경을 되돌릴 수 있는 정보(예: 변경 전 값, 변경된 레코드의 위치)가 기록됩니다.
    *   롤백 시 이 언두 로그를 역순으로 읽어 변경된 데이터를 원래 상태로 복원합니다.
    *   동시성 제어(MVCC)에도 활용되어, 다른 트랜잭션이 커밋되지 않은 변경사항을 보지 않고 이전 버전의 데이터를 읽을 수 있도록 합니다.

*   **롤백 세그먼트 (Rollback Segment):** (주로 Oracle 등 일부 RDBMS에서 사용되는 용어)
    *   언두 로그와 유사하게 트랜잭션의 변경 전 데이터를 저장하는 데이터베이스 내부의 특정 저장 공간입니다.
    *   트랜잭션이 데이터를 수정할 때마다, 수정 전의 데이터 이미지를 롤백 세그먼트에 기록합니다.
    *   롤백이 발생하면, 데이터베이스는 롤백 세그먼트에 저장된 정보를 사용하여 변경된 데이터를 원래 상태로 되돌립니다.
    *   롤백 세그먼트의 크기와 관리 방식은 데이터베이스 성능에 영향을 미칠 수 있습니다.

### 4. 실무에서 주의할 점

*   **언두 공간 부족:** 장시간 실행되거나 대량의 데이터를 변경하는 트랜잭션의 경우, 언두 로그/롤백 세그먼트 공간이 부족해질 수 있습니다. 이는 트랜잭션 실패로 이어질 수 있으므로, 적절한 공간 할당 및 모니터링이 중요합니다.
*   **성능 오버헤드:** 언두 정보를 기록하는 과정 자체는 추가적인 I/O 및 CPU 자원을 소모합니다. 따라서 너무 잦은 대규모 트랜잭션은 시스템 성능에 영향을 줄 수 있습니다.
*   **트랜잭션 격리 수준:** 언두 로그는 MVCC(Multi-Version Concurrency Control) 구현에 필수적이며, 다양한 트랜잭션 격리 수준(예: `READ COMMITTED`, `REPEATABLE READ`)을 지원하는 데 사용됩니다. 격리 수준에 따라 언두 로그의 활용 방식이 달라질 수 있음을 이해해야 합니다.
*   **장애 복구:** 시스템 장애 발생 시, 데이터베이스는 언두 로그를 사용하여 커밋되지 않은 트랜잭션들을 롤백하여 데이터 일관성을 복구합니다.
