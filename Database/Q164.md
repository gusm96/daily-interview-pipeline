## 데이터베이스 인덱스 스캔 방식

면접관님, 데이터베이스에서 인덱스를 활용한 데이터 조회 시, 쿼리 최적화기는 다양한 인덱스 스캔 방식을 고려하여 가장 효율적인 방식을 선택합니다. 대표적인 인덱스 스캔 방식과 그 특징에 대해 설명드리겠습니다.

### 1. Index Unique Scan (인덱스 유니크 스캔)

*   **핵심 정의:** 유니크 인덱스(Primary Key 또는 UNIQUE 제약조건)를 사용하여 정확히 하나의 로우를 찾아내는 가장 효율적인 스캔 방식입니다.
*   **동작 원리:** 인덱스 트리를 루트에서 리프 노드까지 탐색하여, 조건에 해당하는 단 하나의 인덱스 엔트리를 찾고, 해당 엔트리에 저장된 Row ID(또는 물리적 주소)를 통해 테이블 로우에 직접 접근합니다.
*   **성능 영향:** 단일 로우를 조회하는 데 최적화되어 있어 매우 빠릅니다.
*   **선택 쿼리:** `WHERE primary_key_column = 'value'` 또는 `WHERE unique_column = 'value'`와 같이 유니크 제약조건이 있는 컬럼을 동등 조건으로 조회할 때 선택됩니다.

### 2. Index Range Scan (인덱스 범위 스캔)

*   **핵심 정의:** 인덱스를 구성하는 컬럼의 특정 범위 내에 있는 데이터를 조회할 때 사용되는 가장 일반적인 스캔 방식입니다.
*   **동작 원리:** 인덱스 트리를 탐색하여 스캔 시작 지점을 찾은 후, 리프 노드를 따라 순차적으로 스캔하면서 조건에 맞는 인덱스 엔트리들을 찾습니다. 이후 각 엔트리의 Row ID를 사용하여 테이블 로우에 접근합니다.
*   **성능 영향:** 스캔 범위가 넓을수록 성능 저하가 발생할 수 있지만, 테이블 전체를 스캔하는 것보다는 효율적입니다. 인덱스 컬럼의 정렬 순서를 활용하므로 `ORDER BY` 절의 성능 향상에도 기여할 수 있습니다.
*   **선택 쿼리:**
    *   `WHERE indexed_column > 10 AND indexed_column < 100` (범위 조건)
    *   `WHERE indexed_column LIKE 'A%'` (선행 와일드카드 없는 LIKE 조건)
    *   `WHERE indexed_column IN (10, 20, 30)` (IN 조건)
    *   `WHERE indexed_column = 'value' ORDER BY indexed_column` (정렬 조건)

### 3. Index Full Scan (인덱스 전체 스캔)

*   **핵심 정의:** 인덱스 전체를 처음부터 끝까지 스캔하는 방식입니다.
*   **동작 원리:** 인덱스 리프 노드의 첫 번째 블록부터 마지막 블록까지 모든 인덱스 엔트리를 순차적으로 읽습니다.
*   **성능 영향:** 테이블 전체를 스캔하는 것보다 빠를 수 있습니다. 특히, 쿼리가 인덱스 컬럼만으로 구성되어 테이블 접근이 필요 없는 경우(Covering Index) 매우 효율적입니다.
*   **선택 쿼리:**
    *   `SELECT COUNT(*) FROM table_name;` (인덱스에 모든 로우의 엔트리가 있으므로)
    *   `SELECT MIN(indexed_column) FROM table_name;` 또는 `SELECT MAX(indexed_column) FROM table_name;`
    *   `SELECT indexed_column FROM table_name WHERE indexed_column IS NOT NULL;`
    *   쿼리가 인덱스 컬럼만으로 구성되어 테이블 접근이 필요 없는 경우 (Covering Index)

### 4. Index Skip Scan (인덱스 스킵 스캔)

*   **핵심 정의:** 복합 인덱스(Composite Index)에서 선행 컬럼이 조건에 없거나, 조건이 불연속적일 때 인덱스의 선행 컬럼을 '건너뛰면서' 스캔하는 방식입니다.
*   **동작 원리:** 인덱스 선행 컬럼의 고유한 값들을 먼저 찾고, 각 고유 값에 대해 후행 컬럼을 기준으로 Range Scan을 수행하는 방식으로 동작합니다. 마치 여러 개의 작은 Index Range Scan을 수행하는 것과 유사합니다.
*   **성능 영향:** 선행 컬럼의 고유 값 개수가 적고, 후행 컬럼의 조건이 선택적일 때 효율적입니다. 하지만 선행 컬럼의 고유 값이 많으면 성능이 저하될 수 있습니다.
*   **선택 쿼리:** 복합 인덱스 `(col1, col2, col3)`가 있을 때, `WHERE col2 = 'value'` 또는 `WHERE col2 = 'value' AND col3 = 'value'`와 같이 선행 컬럼인 `col1`이 조건에 포함되지 않을 때 고려될 수 있습니다.

### 실무에서 주의할 점

*   **옵티마이저의 선택:** 데이터베이스 옵티마이저는 통계 정보(Statistics)를 기반으로 각 스캔 방식의 비용을 예측하여 가장 효율적인 방식을 선택합니다. 따라서 통계 정보가 최신 상태로 유지되는 것이 중요합니다.
*   **카디널리티와 선택도:** 인덱스 컬럼의 카디널리티(고유 값의 개수)와 쿼리 조건의 선택도(전체 데이터 중 조건에 맞는 데이터의 비율)는 스캔 방식 선택에 큰 영향을 미칩니다. 선택도가 낮을수록(소수의 데이터만 조회할수록) 인덱스 스캔이 유리합니다.
*   **Covering Index:** 쿼리가 필요로 하는 모든 컬럼이 인덱스에 포함되어 있다면, 테이블 접근 없이 인덱스만으로 쿼리를 처리할 수 있어 성능이 크게 향상됩니다. 이를 Covering Index라고 합니다.
*   **인덱스 컬럼 순서:** 복합 인덱스에서 컬럼의 순서는 매우 중요합니다. 일반적으로 자주 사용되는 컬럼이나 선택도가 높은 컬럼을 선행 컬럼으로 두는 것이 좋습니다.
*   **인덱스 남용:** 인덱스는 조회 성능을 향상시키지만, 데이터 변경(INSERT, UPDATE, DELETE) 시 추가적인 오버헤드를 발생시키므로 무분별한 인덱스 생성은 지양해야 합니다.

이러한 인덱스 스캔 방식들을 이해하고 적절히 활용하는 것이 데이터베이스 쿼리 성능 최적화에 핵심적인 요소입니다.
