## 데이터베이스 옵티마이저와 통계 정보 활용

### 1. 핵심 정의

데이터베이스 옵티마이저는 SQL 쿼리를 가장 효율적으로 실행하기 위한 최적의 실행 계획(Execution Plan)을 수립하는 데이터베이스 관리 시스템(DBMS)의 핵심 구성 요소입니다. 이때 통계 정보(Statistics)는 테이블, 인덱스, 컬럼 등에 저장된 데이터의 분포, 개수, 고유 값 수 등을 나타내는 메타데이터로, 옵티마이저가 합리적인 의사결정을 내리는 데 필수적인 자료입니다.

### 2. 동작 원리

옵티마이저는 쿼리 실행 계획을 수립할 때 다음과 같이 통계 정보를 활용합니다.

*   **비용 기반 최적화(Cost-Based Optimization):** 옵티마이저는 각 실행 계획 후보에 대해 예상되는 I/O 비용, CPU 비용 등을 계산하여 가장 낮은 비용의 계획을 선택합니다. 이 비용 계산의 핵심 근거가 바로 통계 정보입니다.
*   **예상 결과 집합 크기 추정:** 특정 조건절(WHERE 절)을 만족하는 행의 수를 통계 정보를 기반으로 추정합니다. 예를 들어, `WHERE status = 'ACTIVE'`와 같은 조건에서 'ACTIVE' 상태의 데이터 비율을 통계에서 확인하여 필터링 후 남을 행의 수를 예측합니다.
*   **조인 순서 및 방식 결정:** 여러 테이블을 조인할 때 어떤 순서로 조인하고, 어떤 조인 방식(Nested Loop, Hash Join, Sort Merge Join 등)을 사용할지 결정합니다. 이때 각 테이블의 크기, 조인 컬럼의 분포 등을 통계 정보로 파악하여 가장 효율적인 방법을 선택합니다.
*   **인덱스 사용 여부 결정:** 특정 컬럼에 인덱스가 존재하더라도, 해당 인덱스를 사용하는 것이 풀 스캔보다 항상 효율적인 것은 아닙니다. 옵티마이저는 통계 정보를 통해 인덱스 스캔 시 예상되는 I/O 비용과 풀 스캔 시 예상되는 I/O 비용을 비교하여 인덱스 사용 여부를 결정합니다.

### 3. 실무에서 주의할 점 및 부정확한 통계 정보의 영향

통계 정보가 최신이 아니거나 부정확할 경우, 옵티마이저는 잘못된 비용 추정을 통해 비효율적인 쿼리 실행 계획을 수립하게 되어 심각한 성능 저하를 초래할 수 있습니다.

*   **구체적인 사례:**
    *   **잘못된 조인 순서:** `ORDERS` 테이블과 `CUSTOMERS` 테이블을 조인하는 쿼리에서, `ORDERS` 테이블의 통계 정보가 오래되어 실제보다 훨씬 작은 테이블로 인식되었다고 가정해봅시다. 옵티마이저는 작은 `ORDERS` 테이블을 먼저 스캔하고 `CUSTOMERS` 테이블을 조인하는 것이 효율적이라고 판단하여 Nested Loop Join을 선택할 수 있습니다. 하지만 실제 `ORDERS` 테이블이 매우 크다면, 이 계획은 엄청난 I/O를 유발하여 성능 저하를 일으킬 것입니다. 반대로 Hash Join이나 Sort Merge Join이 더 적합했을 수 있습니다.
    *   **비효율적인 인덱스 사용:** 특정 컬럼의 데이터 분포가 변경되어 특정 값의 비중이 크게 늘어났음에도 통계 정보가 업데이트되지 않았다고 가정해봅시다. 옵티마이저는 여전히 해당 컬럼의 인덱스를 사용하는 것이 효율적이라고 판단하여 인덱스 스캔을 선택할 수 있습니다. 하지만 실제로는 해당 값의 행이 너무 많아 인덱스 스캔이 풀 테이블 스캔보다 더 많은 I/O를 발생시켜 성능이 저하될 수 있습니다.
    *   **잘못된 필터링 예측:** `WHERE order_date > '2023-01-01'`과 같은 조건에서, 통계 정보가 오래되어 2023년 이후 데이터가 거의 없다고 판단했다고 가정해봅시다. 옵티마이저는 필터링 후 남을 행의 수가 적을 것이라고 예측하고 특정 조인 방식이나 인덱스 사용을 결정합니다. 하지만 실제로는 2023년 이후 데이터가 폭증했다면, 옵티마이저의 예측은 완전히 빗나가게 되고, 선택된 실행 계획은 실제 데이터 양을 처리하는 데 매우 비효율적일 수 있습니다.

*   **주의할 점:**
    *   데이터 변경이 빈번한 테이블은 주기적으로 통계 정보를 갱신해야 합니다.
    *   대량의 데이터 삽입, 삭제, 업데이트 작업 후에는 반드시 통계 정보를 갱신하는 것을 고려해야 합니다.
    *   일부 DBMS는 자동 통계 수집 기능을 제공하지만, 특정 상황에서는 수동 갱신이 필요할 수 있습니다.
    *   통계 정보 갱신 작업 자체도 리소스를 소모하므로, 시스템 부하가 적은 시간에 수행하는 것이 일반적입니다.
