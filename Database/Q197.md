## 데이터베이스 트랜잭션 격리 수준(Isolation Level)

### 1. 핵심 정의

데이터베이스 트랜잭션 격리 수준은 여러 트랜잭션이 동시에 실행될 때, 한 트랜잭션이 다른 트랜잭션의 변경 내용을 얼마나 볼 수 있도록 허용할 것인지를 정의하는 기준입니다. 이는 동시성 제어의 핵심 요소로, 데이터의 일관성을 유지하면서도 시스템의 처리량을 최적화하는 데 중요한 역할을 합니다.

### 2. 동작 원리 및 각 격리 수준별 락(Lock) 구현 예시

각 격리 수준은 특정 종류의 동시성 문제(Dirty Read, Non-Repeatable Read, Phantom Read)를 방지하기 위해 내부적으로 다양한 락 메커니즘을 사용합니다.

*   **READ UNCOMMITTED (가장 낮은 격리 수준)**
    *   **정의:** 다른 트랜잭션이 커밋하지 않은 변경 사항도 읽을 수 있도록 허용합니다.
    *   **동작 원리:** Dirty Read를 허용하므로, 일반적으로 읽기 작업에 락을 거의 사용하지 않거나 매우 짧은 시간 동안만 사용합니다.
    *   **락 예시:** 읽기 시 공유 락(Shared Lock)을 걸지 않거나, 매우 짧은 시간 동안만 걸고 바로 해제합니다. 쓰기 시에는 배타 락(Exclusive Lock)을 사용합니다.
    *   **방지하는 동시성 문제:** 없음 (모든 동시성 문제 발생 가능)

*   **READ COMMITTED**
    *   **정의:** 커밋된 데이터만 읽을 수 있도록 보장하여 Dirty Read를 방지합니다.
    *   **동작 원리:** 트랜잭션이 데이터를 읽을 때 해당 데이터에 대한 공유 락을 획득하고, 읽기가 완료되면 즉시 락을 해제합니다. 쓰기 시에는 배타 락을 사용하며, 트랜잭션이 커밋되거나 롤백될 때까지 유지합니다.
    *   **락 예시:**
        *   `SELECT * FROM accounts WHERE id = 1;` 실행 시, `id = 1` 레코드에 대한 공유 락을 획득하고 읽기 완료 후 즉시 해제합니다.
        *   다른 트랜잭션이 해당 레코드를 업데이트하고 커밋하기 전까지는 이전 커밋된 값을 읽습니다.
    *   **방지하는 동시성 문제:** Dirty Read

*   **REPEATABLE READ**
    *   **정의:** 트랜잭션 내에서 동일한 쿼리를 여러 번 실행했을 때 항상 같은 결과를 반환하도록 보장합니다. Dirty Read와 Non-Repeatable Read를 방지합니다.
    *   **동작 원리:** 트랜잭션이 데이터를 읽을 때 해당 데이터에 대한 공유 락을 획득하고, 트랜잭션이 종료될 때까지 락을 유지합니다. 쓰기 시에는 배타 락을 사용하며, 트랜잭션 종료 시까지 유지합니다. 또한, 일반적으로 범위 락(Range Lock) 또는 넥스트 키 락(Next-Key Lock)을 사용하여 Phantom Read를 부분적으로 방지합니다.
    *   **락 예시 (MySQL InnoDB 기준):**
        *   `SELECT * FROM products WHERE category = 'electronics';` 실행 시, 'electronics' 카테고리에 해당하는 모든 레코드에 공유 락을 걸고 트랜잭션 종료 시까지 유지합니다.
        *   또한, 해당 범위에 대한 넥스트 키 락을 사용하여 다른 트랜잭션이 이 범위에 새로운 레코드를 삽입하는 것을 방지할 수 있습니다.
    *   **방지하는 동시성 문제:** Dirty Read, Non-Repeatable Read (Phantom Read는 부분적으로 방지)

*   **SERIALIZABLE (가장 높은 격리 수준)**
    *   **정의:** 모든 트랜잭션을 순차적으로 실행하는 것과 동일한 결과를 보장합니다. 모든 동시성 문제를 방지합니다.
    *   **동작 원리:** 트랜잭션이 읽거나 쓰는 모든 데이터에 대해 락을 획득하고, 트랜잭션이 종료될 때까지 유지합니다. 일반적으로 읽기 시에도 공유 락을 사용하며, 쿼리 조건에 해당하는 모든 범위에 대해 락을 걸어 Phantom Read를 완벽하게 방지합니다.
    *   **락 예시:**
        *   `SELECT * FROM orders WHERE amount > 1000;` 실행 시, `amount > 1000` 조건을 만족하는 모든 레코드에 공유 락을 걸고, 해당 조건에 대한 인덱스 범위 락(Range Lock) 또는 테이블 락(Table Lock)을 사용하여 다른 트랜잭션이 이 범위에 새로운 레코드를 삽입하거나 기존 레코드를 변경하는 것을 완벽하게 차단합니다.
    *   **방지하는 동시성 문제:** Dirty Read, Non-Repeatable Read, Phantom Read

### 3. 특정 격리 수준 선택 시 고려해야 할 트레이드오프

격리 수준을 선택할 때는 **데이터 일관성**과 **동시성/성능** 사이의 트레이드오프를 고려해야 합니다.

*   **높은 격리 수준 (예: SERIALIZABLE)**
    *   **장점:** 데이터 일관성이 가장 높고, 모든 동시성 문제를 완벽하게 방지합니다.
    *   **단점:** 락 경합이 심해져 동시성이 크게 저하되고, 시스템 처리량이 감소하며, 교착 상태(Deadlock) 발생 가능성이 높아집니다. 이는 성능 저하로 이어집니다.

*   **낮은 격리 수준 (예: READ UNCOMMITTED, READ COMMITTED)**
    *   **장점:** 락 경합이 적어 동시성이 높고, 시스템 처리량이 좋습니다.
    *   **단점:** Dirty Read, Non-Repeatable Read, Phantom Read와 같은 동시성 문제가 발생할 수 있어 데이터 일관성이 저해될 위험이 있습니다. 애플리케이션 레벨에서 추가적인 동시성 제어 로직이 필요할 수 있습니다.

**일반적인 선택:**
대부분의 웹 애플리케이션에서는 **READ COMMITTED** 또는 **REPEATABLE READ**를 기본 격리 수준으로 사용합니다.

*   **READ COMMITTED:** Dirty Read를 방지하면서도 비교적 높은 동시성을 제공하여 가장 널리 사용됩니다.
*   **REPEATABLE READ:** Non-Repeatable Read까지 방지해야 하는 경우 선택하며, MySQL InnoDB의 기본 격리 수준입니다. Phantom Read는 넥스트 키 락으로 부분적으로 방지됩니다.

애플리케이션의 요구사항(데이터 일관성의 중요도, 예상되는 동시성 트랜잭션 수, 성능 목표)을 면밀히 분석하여 적절한 격리 수준을 선택하는 것이 중요합니다.
