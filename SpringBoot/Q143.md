# [Q143] Spring MVC의 HandlerMethodArgumentResolver 활용

## HandlerMethodArgumentResolver

### 1. 핵심 정의

`HandlerMethodArgumentResolver`는 Spring MVC에서 컨트롤러 메서드의 인자를 유연하게 처리하고 바인딩하기 위한 핵심 인터페이스입니다. 이 인터페이스는 특정 조건에 맞는 인자 타입을 지원하는지(`supportsParameter`)와 실제 인자 값을 생성하여 반환하는(`resolveArgument`) 두 가지 주요 메서드를 가집니다.

### 2. 동작 원리

Spring MVC는 요청이 들어오면 `DispatcherServlet`을 통해 `HandlerAdapter`를 찾고, `HandlerAdapter`는 컨트롤러 메서드를 호출하기 전에 해당 메서드의 각 인자에 대해 등록된 `HandlerMethodArgumentResolver`들을 순회합니다. 각 리졸버는 `supportsParameter`를 호출하여 현재 인자를 처리할 수 있는지 확인하고, 처리할 수 있는 리졸버가 발견되면 `resolveArgument`를 호출하여 실제 인자 값을 생성하고 컨트롤러 메서드에 전달합니다.

### 3. 실무에서 주의할 점 및 커스텀 구현

`HandlerMethodArgumentResolver`의 커스텀 구현은 Spring이 기본적으로 제공하는 바인딩 방식(예: `@RequestParam`, `@RequestBody`, `@ModelAttribute`)으로는 처리하기 어려운 복잡하거나 반복적인 인자 바인딩 로직을 추상화하고 재사용성을 높일 때 유용합니다.

**커스텀 구현이 필요한 상황:**

*   **특정 도메인 객체 자동 생성:** 여러 요청 파라미터나 세션 정보를 조합하여 특정 도메인 객체를 생성해야 할 때.
*   **인증/인가 정보 주입:** 현재 로그인한 사용자 정보나 권한 정보를 컨트롤러 메서드 인자로 직접 주입하고 싶을 때.
*   **복잡한 데이터 변환:** 특정 형식의 문자열을 복잡한 비즈니스 로직을 거쳐 특정 객체로 변환해야 할 때.
*   **반복적인 로직 추상화:** 여러 컨트롤러에서 동일하게 사용되는 인자 처리 로직을 한 곳으로 모아 관리하고 싶을 때.

**실제 구현 시 얻을 수 있는 이점 (구체적인 예시):**

*   **코드 간결성 및 가독성 향상:** 컨트롤러 메서드에서 반복적인 인자 처리 로직을 제거하여 비즈니스 로직에만 집중할 수 있게 합니다.
    *   **예시:** 현재 로그인한 사용자 정보를 나타내는 `CurrentUser` 객체를 컨트롤러 메서드 인자로 바로 주입받고 싶을 때.
        ```java
        // 컨트롤러 메서드
        @GetMapping("/profile")
        public String getUserProfile(@CurrentUser User user) {
            // user 객체를 바로 활용
            return "User: " + user.getUsername();
        }

        // Custom HandlerMethodArgumentResolver 구현
        public class CurrentUserArgumentResolver implements HandlerMethodArgumentResolver {
            @Override
            public boolean supportsParameter(MethodParameter parameter) {
                return parameter.hasParameterAnnotation(CurrentUser.class) && parameter.getParameterType().equals(User.class);
            }

            @Override
            public Object resolveArgument(MethodParameter parameter, ModelAndViewContainer mavContainer,
                                          NativeWebRequest webRequest, WebDataBinderFactory binderFactory) throws Exception {
                // 세션 또는 SecurityContext에서 사용자 정보를 가져와 User 객체 생성 및 반환
                return (User) webRequest.getAttribute("currentUser", RequestAttributes.SCOPE_SESSION);
            }
        }
        ```
*   **재사용성 증대:** 한 번 구현한 리졸버는 여러 컨트롤러 메서드에서 재사용될 수 있어 개발 효율성을 높입니다.
*   **테스트 용이성:** 인자 바인딩 로직이 컨트롤러에서 분리되어 단위 테스트하기 용이해집니다.
*   **유지보수 용이성:** 인자 처리 로직 변경 시 해당 리졸버만 수정하면 되므로 유지보수가 편리합니다.
