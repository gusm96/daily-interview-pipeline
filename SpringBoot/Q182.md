# [Q182] Spring Boot 애플리케이션의 Graceful Shutdown 구현

## Graceful Shutdown 구현 및 고려사항

### 1. 핵심 정의

Graceful Shutdown은 애플리케이션이 종료되거나 재시작될 때, 현재 처리 중인 요청을 완료하고 새로운 요청을 받지 않도록 하여 서비스 중단을 최소화하는 과정입니다. 이를 통해 사용자 경험 저하를 방지하고 데이터 일관성을 유지할 수 있습니다.

### 2. 동작 원리 (Spring Boot 기준)

Spring Boot는 기본적으로 `server.shutdown=graceful` 설정을 통해 Graceful Shutdown을 지원합니다.

*   **SIGTERM 수신:** 애플리케이션이 종료 신호(SIGTERM)를 받으면, 즉시 새로운 요청 수신을 중단합니다.
*   **진행 중인 요청 처리:** 이미 수신되어 처리 중인 요청들은 설정된 타임아웃(`spring.lifecycle.timeout-per-shutdown-phase`) 내에 완료될 때까지 기다립니다.
*   **리소스 정리:** 모든 요청 처리가 완료되거나 타임아웃이 발생하면, 애플리케이션 컨텍스트를 종료하고 관련 리소스(DB 커넥션 풀, 메시지 큐 리스너 등)를 정리합니다.

### 3. 실무에서 주의할 점

*   **타임아웃 설정:** `spring.lifecycle.timeout-per-shutdown-phase` 값을 적절히 설정해야 합니다. 너무 짧으면 진행 중인 요청이 강제 종료될 수 있고, 너무 길면 배포 시간이 지연될 수 있습니다. 일반적으로 가장 긴 요청 처리 시간을 고려하여 설정합니다.
*   **외부 의존성 처리:** 데이터베이스 커넥션 풀, 메시지 큐 리스너, 스케줄러 등 외부 의존성을 사용하는 경우, 이들이 Graceful Shutdown 과정에서 안전하게 종료되거나 정리되는지 확인해야 합니다. 예를 들어, 메시지 큐 리스너는 새로운 메시지 폴링을 중단하고 현재 처리 중인 메시지를 완료해야 합니다.
*   **로드 밸런서/API 게이트웨이 연동:**
    *   **헬스 체크:** 배포 전, 로드 밸런서에서 해당 인스턴스를 트래픽 분배 대상에서 제외하고, 헬스 체크가 실패하도록 설정하여 새로운 요청이 유입되지 않도록 합니다.
    *   **연결 드레인(Connection Draining):** 로드 밸런서의 연결 드레인 기능을 활용하여 기존 연결에 대한 요청이 모두 처리될 때까지 기다린 후, 해당 인스턴스로의 트래픽을 완전히 차단합니다.
*   **비동기 작업 및 스레드 관리:** 애플리케이션 내에서 별도의 스레드 풀을 사용하거나 비동기 작업을 수행하는 경우, 이들이 Graceful Shutdown 과정에서 적절히 종료되도록 관리해야 합니다. `ExecutorService`의 `shutdown()` 및 `awaitTermination()` 메서드를 활용하는 것이 일반적입니다.
*   **분산 트랜잭션:** 분산 트랜잭션을 사용하는 경우, Graceful Shutdown 중 트랜잭션이 중간에 끊기지 않도록 주의해야 합니다. 트랜잭션 커밋/롤백이 완료된 후에 종료되도록 설계해야 합니다.
*   **로그 확인:** Graceful Shutdown 과정에서 발생하는 로그를 면밀히 확인하여 예상치 못한 오류나 지연이 없는지 검토해야 합니다.
