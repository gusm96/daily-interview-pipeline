## Spring Data JPA Query By Example (QBE)

### 1. 핵심 정의
Query By Example(QBE)은 Spring Data JPA에서 엔티티 객체를 쿼리 조건의 "예제"로 사용하여 동적으로 쿼리를 생성하는 방법입니다. 복잡한 쿼리 DSL이나 JPQL 없이도 간단한 조건으로 데이터베이스를 조회할 수 있도록 설계되었습니다.

### 2. 동작 원리
QBE는 `Example` 객체를 생성하여 쿼리를 수행합니다. `Example` 객체는 다음 세 가지 요소로 구성됩니다.
*   **Probe (프로브):** 쿼리 조건으로 사용될 엔티티 인스턴스입니다. 프로브 객체에 설정된 `null`이 아닌 필드 값들이 쿼리 조건으로 사용됩니다.
*   **Matcher (매처):** 프로브의 필드 값들이 어떻게 매칭될지 정의합니다. 예를 들어, `startsWith`, `endsWith`, `contains`, `ignoreCase` 등을 설정할 수 있습니다.
*   **Example (예제):** 프로브와 매처를 포함하는 최종 쿼리 정의 객체입니다.
Spring Data JPA는 이 `Example` 객체를 기반으로 내부적으로 `WHERE` 절을 동적으로 생성하여 데이터베이스 쿼리를 실행합니다. 기본적으로는 모든 조건이 `AND`로 연결되며, `null` 값은 무시됩니다.

### 3. 실무에서 주의할 점 및 활용 시 고려사항
*   **활용 시 효과적인 경우:**
    *   **간단한 동적 쿼리:** 검색 필드가 많지 않고, 대부분 `AND` 조건으로 연결되는 간단한 검색 기능 구현에 매우 유용합니다.
    *   **부분 일치 검색:** `Matcher`를 통해 `startsWith`, `endsWith`, `contains`와 같은 부분 일치 검색을 쉽게 구현할 수 있습니다.
    *   **개발 생산성 향상:** JPQL이나 QueryDSL 없이 엔티티 객체만으로 쿼리를 구성하므로 개발 속도를 높일 수 있습니다.
*   **제약사항 및 주의점:**
    *   **`OR` 조건의 어려움:** QBE는 기본적으로 모든 조건을 `AND`로 연결합니다. 복잡한 `OR` 조건이나 중첩된 논리 연산이 필요한 쿼리에는 적합하지 않습니다.
    *   **`JOIN`의 제한:** 엔티티 간의 복잡한 `JOIN`을 직접적으로 표현하기 어렵습니다. 연관 관계를 통한 조회가 가능하지만, 세밀한 제어는 어렵습니다.
    *   **특정 연산자 부재:** `>` (크다), `<` (작다), `NOT IN` 등 다양한 비교 연산자를 직접적으로 지원하지 않습니다.
    *   **성능 고려:** 복잡한 쿼리나 대량의 데이터 처리 시에는 QBE가 생성하는 쿼리가 최적화되지 않을 수 있으므로, 성능에 민감한 부분에서는 JPQL이나 QueryDSL을 고려해야 합니다.
    *   **`null` 값 처리:** 프로브 객체의 `null` 필드는 쿼리 조건에서 제외됩니다. `null` 값을 포함하는 필드를 검색하려면 다른 방법을 사용해야 합니다.
