## 운영체제 파일 시스템의 저널링(Journaling) 기법

### 1. 핵심 정의

저널링은 파일 시스템의 메타데이터 변경 사항을 실제 디스크에 반영하기 전에 미리 로그(저널)에 기록하는 기법입니다. 시스템 충돌이나 전원 장애 발생 시 파일 시스템의 일관성을 유지하고 데이터 손상을 방지하여 데이터 무결성을 보장합니다.

### 2. 동작 원리

*   **로그 기록:** 파일 생성, 삭제, 이름 변경 등 메타데이터 변경이 발생하면, 실제 디스크에 쓰기 전에 해당 변경 내용을 저널 영역에 먼저 기록합니다. 이 기록은 트랜잭션 형태로 이루어지며, 변경 전/후 상태를 포함할 수 있습니다.
*   **커밋:** 저널 기록이 성공적으로 완료되면, 해당 트랜잭션이 "커밋"되었다고 표시합니다.
*   **실제 디스크 반영:** 커밋된 트랜잭션에 따라 실제 파일 시스템의 메타데이터를 디스크에 반영합니다.
*   **저널 삭제:** 실제 디스크 반영이 완료되면, 저널에서 해당 트랜잭션 기록을 삭제합니다.
*   **복구:** 시스템 충돌 발생 시, 파일 시스템은 재부팅 후 저널을 검사합니다. 커밋되었지만 실제 디스크에 반영되지 않은 트랜잭션이 있다면, 저널의 내용을 기반으로 파일 시스템을 복구하여 일관된 상태로 되돌립니다.

### 3. 실무에서 주의할 점 (트레이드오프)

*   **성능 오버헤드:** 저널링은 모든 메타데이터 변경에 대해 추가적인 디스크 쓰기 작업(저널 기록)을 요구하므로, 저널링이 없는 파일 시스템에 비해 쓰기 성능 저하가 발생할 수 있습니다.
*   **디스크 공간 사용:** 저널을 저장하기 위한 별도의 디스크 공간이 필요합니다.
*   **복구 시간:** 충돌 후 복구 시 저널의 크기와 복구해야 할 트랜잭션 수에 따라 복구 시간이 달라질 수 있습니다. 일반적으로 저널링이 없는 파일 시스템의 전체 파일 시스템 검사(fsck)보다 훨씬 빠릅니다.
*   **데이터 무결성 보장:** 저널링은 시스템 충돌 시 파일 시스템의 메타데이터 일관성을 강력하게 보장하여 데이터 손실 및 파일 시스템 손상을 최소화합니다. 저널링이 없는 파일 시스템은 충돌 시 파일 시스템 전체를 검사해야 하며, 이 과정에서 데이터 손실이나 파일 시스템 손상이 발생할 가능성이 높습니다.
*   **다양한 저널링 모드:** 파일 시스템은 일반적으로 여러 저널링 모드(예: writeback, ordered, data)를 제공하며, 각 모드는 성능과 데이터 무결성 보장 수준에서 다른 트레이드오프를 가집니다. 예를 들어, `data` 저널링은 메타데이터와 데이터 모두를 저널링하여 가장 높은 무결성을 제공하지만, 가장 큰 성능 오버헤드를 발생시킵니다.
