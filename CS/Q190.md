## 가상 메모리 주소 공간 접근 권한 관리 및 프로세스 간 메모리 보호

### 1. 핵심 정의

운영체제는 **가상 메모리(Virtual Memory)**를 통해 각 프로세스에 독립적인 가상 주소 공간을 제공합니다. 이 가상 주소 공간은 실제 물리 메모리와 분리되어 있으며, **메모리 관리 장치(MMU: Memory Management Unit)**와 운영체제의 협력을 통해 접근 권한이 관리됩니다. 이를 통해 한 프로세스가 다른 프로세스의 메모리 영역을 침범하는 것을 방지하여 **메모리 보호(Memory Protection)**를 달성합니다.

### 2. 동작 원리

*   **페이지 테이블(Page Table)**: 각 프로세스는 자신만의 페이지 테이블을 가집니다. 이 테이블은 가상 주소와 물리 주소 간의 매핑 정보를 담고 있으며, 각 페이지 엔트리에는 해당 페이지에 대한 **접근 권한 비트(Access Permission Bits)**가 포함됩니다. 이 비트는 읽기(Read), 쓰기(Write), 실행(Execute) 등의 권한을 명시합니다.
*   **MMU의 역할**: CPU가 가상 주소에 접근을 시도하면, MMU는 해당 가상 주소를 페이지 테이블을 참조하여 물리 주소로 변환합니다. 이때 MMU는 페이지 엔트리에 명시된 접근 권한 비트를 확인하여 현재 요청된 접근(예: 쓰기)이 허용되는지 검사합니다.
*   **권한 위반 처리**: 만약 요청된 접근이 허용되지 않는다면, MMU는 **페이지 폴트(Page Fault)** 또는 **세그멘테이션 폴트(Segmentation Fault)**와 같은 예외를 발생시켜 CPU에 알립니다. 운영체제는 이 예외를 처리하여 해당 프로세스를 종료시키거나 시그널을 보내는 등의 조치를 취함으로써 불법적인 메모리 접근을 차단합니다.

### 3. 실무에서 주의할 점

*   **메모리 누수 및 오버플로우**: 가상 메모리 보호는 불법적인 접근을 막지만, 프로세스 내부의 메모리 누수나 버퍼 오버플로우와 같은 논리적 오류까지 방지하지는 못합니다. 이러한 문제는 여전히 애플리케이션 레벨에서 주의 깊게 관리해야 합니다.
*   **권한 설정의 중요성**: 페이지 테이블의 접근 권한 설정은 보안에 매우 중요합니다. 불필요하게 넓은 권한을 부여하면 잠재적인 보안 취약점이 될 수 있으므로, 최소 권한의 원칙(Principle of Least Privilege)에 따라 필요한 최소한의 권한만 부여해야 합니다.
*   **공유 메모리 관리**: 여러 프로세스가 공유 메모리를 사용하는 경우, 각 프로세스의 페이지 테이블에서 해당 공유 메모리 영역에 대한 접근 권한을 적절히 설정하고, 동기화 메커니즘을 통해 데이터 일관성을 유지하는 것이 중요합니다.
