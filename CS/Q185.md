## 메모리 보호 메커니즘

### 1. 핵심 정의
메모리 보호 메커니즘은 운영체제에서 실행 중인 프로세스들이 서로의 메모리 영역을 침범하거나, 운영체제의 커널 영역을 침범하는 것을 방지하여 시스템의 안정성과 보안을 유지하는 기술입니다. 이는 각 프로세스가 독립적인 메모리 공간을 사용하는 것처럼 보이게 하고, 비정상적인 접근으로부터 시스템을 보호합니다.

### 2. 동작 원리 및 구현 기법

#### 가. 세그멘테이션 (Segmentation)
*   **동작 원리:** 프로그램을 논리적인 단위(코드, 데이터, 스택 등)인 세그먼트로 나누고, 각 세그먼트에 대해 시작 주소와 길이를 부여하여 메모리에 배치합니다. CPU는 논리 주소(세그먼트 번호, 오프셋)를 물리 주소로 변환하며, 이때 세그먼트의 길이를 벗어나는 접근을 감지하여 보호합니다.
*   **장점:**
    *   프로그램의 논리적 구조를 반영하여 메모리를 관리하므로, 코드 공유 및 재배치가 용이합니다.
    *   각 세그먼트에 대해 접근 권한(읽기, 쓰기, 실행)을 부여하여 세밀한 보호가 가능합니다.
*   **단점:**
    *   서로 다른 크기의 세그먼트들이 메모리에 할당되고 해제되면서 외부 단편화(External Fragmentation)가 발생할 수 있습니다.
    *   세그먼트 크기가 가변적이므로 메모리 할당 및 관리가 복잡해질 수 있습니다.

#### 나. 페이징 (Paging)
*   **동작 원리:** 물리 메모리를 고정된 크기의 프레임(Frame)으로, 논리 메모리를 동일한 크기의 페이지(Page)로 나눕니다. 각 프로세스의 페이지는 물리 메모리의 비연속적인 프레임에 할당될 수 있으며, 페이지 테이블을 통해 논리 주소(페이지 번호, 오프셋)를 물리 주소로 변환합니다. 페이지 테이블 엔트리에는 접근 권한 비트가 포함되어 있어 메모리 보호를 수행합니다.
*   **장점:**
    *   고정된 크기의 페이지를 사용하므로 외부 단편화가 발생하지 않습니다.
    *   메모리 할당 및 관리가 비교적 간단하며, 가상 메모리 구현에 효율적입니다.
*   **단점:**
    *   페이지 크기가 너무 작으면 페이지 테이블의 크기가 커져 메모리 오버헤드가 발생할 수 있습니다.
    *   페이지 크기가 너무 크면 내부 단편화(Internal Fragmentation)가 발생할 수 있습니다.
    *   프로그램의 논리적 구조를 반영하지 못하므로, 세그멘테이션에 비해 코드 공유 및 보호가 덜 직관적일 수 있습니다.

### 3. 실무에서 주의할 점
*   **성능 오버헤드:** 메모리 보호 메커니즘은 주소 변환 과정에서 추가적인 CPU 사이클을 소모하므로, 성능 오버헤드를 최소화하는 것이 중요합니다. TLB(Translation Lookaside Buffer)와 같은 캐싱 기법을 활용하여 주소 변환 속도를 높입니다.
*   **보안 취약점:** 메모리 보호 메커니즘이 완벽하더라도, 버퍼 오버플로우나 포맷 스트링 버그와 같은 소프트웨어 취약점을 통해 메모리 보호를 우회하려는 시도가 있을 수 있습니다. 따라서 안전한 코딩 습관과 추가적인 보안 메커니즘(ASLR, DEP 등)을 함께 고려해야 합니다.
*   **운영체제 설계:** 현대 운영체제는 일반적으로 세그멘테이션과 페이징을 혼합하여 사용합니다. 예를 들어, 세그멘테이션으로 논리적인 영역을 나누고, 각 세그먼트 내부를 페이징으로 관리하여 두 기법의 장점을 모두 활용합니다. 이러한 복합적인 구조를 이해하고 설계에 반영하는 것이 중요합니다.
